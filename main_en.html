Cache Terms from RFC 2616

These terms describe how caching works in HTTP to improve performance and reduce server load.

1

public

The public directive explicitly allows any type of cache—whether a browser or a shared proxy—to store the response. This is useful for static or openly accessible content where sharing cached copies improves load time and reduces server requests.
Example: Cache-Control: public, max-age=3600 enables caching for one hour.

2

private

The private directive indicates that the response is meant for a single user only and must not be stored by shared caches. It ensures that personalized or sensitive information remains accessible only through the user’s own browser cache and not by public or proxy caches.
Example: Cache-Control: private, max-age=600 stores the data only for the individual user for 10 minutes.

3

no-cache

The no-cache directive requires caches to revalidate the stored response with the origin server before reusing it. Although the response can be stored locally, it cannot be served to the client unless the server confirms that it has not changed. This guarantees freshness while still providing caching benefits.
Example: Cache-Control: no-cache forces validation before reuse.

4

no-store

The no-store directive is the strictest form of cache control, completely preventing any storage of the request or response. It is designed for highly confidential information, ensuring that no data is written to disk or memory where it could later be accessed.
Example: Cache-Control: no-store is often used for login pages or financial transactions.

5

max-age

The max-age directive defines the maximum time period (in seconds) during which a cached response is considered fresh. Within this time, the cache can serve the stored response without contacting the server. After it expires, the cache must revalidate or fetch a new version.
Example: Cache-Control: max-age=300 allows reuse of the cached content for five minutes.
